================================================================================
DASHBOARD GÉNIE INDUSTRIEL (ENIB) - SPÉCIFICATIONS DÉTAILLÉES DU PROJET
================================================================================

1. INTRODUCTION
---------------
Le Dashboard GI est un système de pilotage de la performance académique et 
administrative pour le département Génie Industriel de l'ENIB. Il transforme 
des données brutes issues de Supabase et Google Sheets en graphiques décisionnels.

2. STACK TECHNIQUE (DÉTAILLÉE)
------------------------------

A. FRONTEND (React App)
- Framework : Vite v5 + React v18 + TypeScript
- Styling : Tailwind CSS (Utilisation de CSS-variables pour le thème dynamique)
- UI Library : Radix UI / Shadcn UI
- Graphiques : Recharts (RadarChart, Heatmap, PieChart, AreaChart, BarChart)
- Gestion d'état : React Hooks (UseEffect, UseState, Custom Hooks)
- Routage : React Router DOM
- Icons : Lucide-React
- Date management : date-fns

B. BACKEND (API Express)
- Runtime : Node.js
- Framework : Express.js
- Auth Integration : Middleware de vérification de Token (Supabase JWT)
- Data Fetching : Axios (pour Google Sheets), Supabase JS Client
- Automation : Node-Cron (pour les rapports hebdomadaires par email)
- Emailing : Nodemailer (via SMTP Gmail)

C. INFRASTRUCTURE & DATABASE
- Base de données : Supabase (PostgreSQL)
- Stockage externe : Google Sheets (CSV Export API)
- Hosting Frontend : Vercel
- Hosting Backend : Render (Service Web Node.js)

4. ARCHITECTURE DES DONNÉES (SUPABASE)
--------------------------------------
Principales tables utilisées :
- etudiants : id, nom, prenom, niveau, classe, double_diplome
- resultats_examens : moyenne, admis, session_admission, id_etudiant, id_matiere
- absences_etudiants : nb_justifiees, nb_injustifiees, mois, id_etudiant
- permanents : nom, prenom, grade, statut
- charge_permanents : heures_statutaires, heures_realisees, heures_cm/td/tp
- pfe_fiches / pfe_evaluation : Suivi des stages et notes
- partenariats / conventions : Suivi des relations industrielles

5. DOCUMENTATION DES API (ENDPOINTS)
------------------------------------
Tous les endpoints sont préfixés par /api/

- MODULE 1 (Enseignement) : GET /enseignement/kpis
- MODULE 2 (RH) : GET /rh/kpis
- MODULE 3 (Encadrement) : GET /encadrement/kpis
- MODULE 4 (Satisfaction) : GET /satisfaction/kpis | POST /satisfaction/import
- MODULE 5 (Rayonnement) : GET /rayonnement/kpis
- EXPORT : GET /export/pdf (Génération de rapports)
- HEALTH : GET /health (Public)

6. LOGIQUE MÉTIER & KPIs (RÉSUMÉ)
---------------------------------
- Alertes : Détectées par croisement (Moyenne < 10 AND Absences Injustifiées > 30%).
- Occupation RH : Ratio entre heures réalisées et quota statutaire.
- Satisfaction : Moyenne pondérée des scores issus des formulaires Google.
- Insertion : Pourcentage de "Oui" dans le champ 'embauche' des fiches PFE.

7. CONFIGURATION DES VARIABLES D'ENVIRONNEMENT
----------------------------------------------
- SUPABASE_URL / SERVICE_KEY : Connexion à la DB.
- GOOGLE_SHEETS_ID : Identifiant du tableur public.
- ANNEE_UNIV : Année par défaut (ex: 2024-2025).
- SMTP_USER / SMTP_PASS : Identifiants pour l'envoi de rapports.
- VITE_EXPRESS_URL (Frontend) : URL du backend sur Render.

8. MAINTENANCE ET RÉCUPÉRATION
------------------------------
- Redéploiement : En cas de modification de .env sur Render/Vercel, un redéploiement manuel est nécessaire.
- Google Sheets : Le partage doit être "Public - Lecteur" pour permettre l'extraction CSV via l'URL gviz.
- Sécurité : Le middleware verifyToken assure que seuls les utilisateurs authentifiés via Supabase Auth peuvent accéder aux données.
